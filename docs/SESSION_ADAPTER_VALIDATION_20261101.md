## Contract

`wx_agent.session_adapter` accepts only an explicit `ManagedSession` with `provider=codex`, `ownership=managed-app-server`, a persisted thread ID, host, project working directory and private local lock path. Explicit provisioning allocates once with `thread/start`, saves the original reference before mutation, runs one read-only initialization checkpoint with no WeChat content, and cold-resumes the same ID before recording ready. Later connections resume that ID before thread/read; a new thread is never substituted for a failed resume. Installed `codex app-server --help` confirms `--stdio`. It does not read, copy, rewrite or delete Codex rollout archives. A desktop-owned thread is rejected because this transport cannot prove exclusive ownership against the desktop app.

`RustDeliveryEvidence` calls the coordinator's `inbox reserve-turn` and `inbox record-turn` commands. A `Delivery` includes the Rust claim's owner, epoch and token, which are passed to this backend but omitted from the model prompt. Its `reserve` operation must atomically commit the delivery's session and attempted state **before** `turn/start`; `record_turn` binds the returned turn ID. An existing reservation, active thread, failed status read, lost response or failed evidence write never triggers automatic retry. The caller must inspect the original thread and Rust evidence before a human-approved recovery decision. `clientUserMessageId` carries the delivery ID for correlation, but this implementation does not assume server-side deduplication. The adapter does not interpret model output as an inbox completion or outgoing WeChat intent. The trusted `command_hint` may give the model the private runtime CLI path for `show` and `complete`; the claim token itself is never included by the adapter in the prompt.

For owner configuration, persist the returned `ManagedSession` fields and use one shared lock path for all local workers targeting that managed thread. The adapter checks the configured host against its local hostname. Its local lock stays held from before status/resume through the managed turn's terminal state, observed by `turn_status`, or until the owned app-server process is closed. A second adapter returns busy without resuming the thread. The Rust inbox owner generation and lease must fence routing before calling `deliver`; that wiring belongs to the coordinator. Rust must additionally reject a different delivery reserving the same `session_ref` while a prior transport reservation remains unresolved, including after an unclean worker exit. Cross-host transport is not implemented. An explicit interrupt request is limited to the exact turn held by that adapter; the lock remains until terminal evidence or owned-transport shutdown. A local lock cannot protect a thread independently opened by the desktop app.
