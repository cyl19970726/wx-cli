## 内容与状态契约

`conversations send-image --request-id ID --image PATH` 接受单帧 PNG/JPEG 的真实文件内容。上限为 16 MiB、每边 8192 像素、总像素 4000 万；拒绝其他格式、动画／多图、损坏、超限和符号链接输入。文件后缀不决定格式。中文和空格文件名按一个路径参数传入。图片无附带文字；如需说明，另建一个独立文字意图。

Rust 在入队前完整解码验证，复制精确原始字节到该 channel 的私有 `outgoing-media/`，并在现有 journal 绑定请求、channel/session、媒体类型、字节数和 SHA-256。同一 ID 换图冲突；队列建立后原文件变化不改变冻结意图；冻结副本损坏或丢失拒绝发送。Python 将预期 SHA-256 传入 Rust，输入在两层间变化会在创建意图和 GUI 前停止；保存后再次核对媒体身份。

旧文字意图、attempt、证据和 consumer 保留。SQLite migration 在事务内扩展意图表；文字仍用协议 1，图片用协议 2 的 `media:{path,sha256,mime_type,size_bytes}`。图片待发状态为 `media_queued`，使旧二进制的 `status='queued'` 领取逻辑无法误发图片。旧版可继续处理文字，但不可用于操作／恢复图片；不回滚 journal 或删除新进度。图片没有 `recover-unsent` 支持，任何已尝试／未知结果均保留原 ID 停发。

## 图片证据

发送前后使用同一目标、focus 证据、窗口、共享 UI 锁和 attempt。图片准备要求已验证的空输入框参考与空 expectedDraft；不替换用户草稿。原生助手在准备和提交前核对冻结文件并解码，粘贴真实图片，复制输入框中的图片并比较规范化像素；不以路径文字或纯文本复制结果代替图片。发送只点击一次，保留持久提交标记及提交后的窗口截图／摘要。

Python 要求图片专用原生证明匹配媒体摘要和准备像素，核验提交后截图完整性，再在加密副本事件中选择提交前游标之后、正确 talker／self、唯一的新出站 Image 候选。随后通过 Rust 只读 `outbox verify-image-event` 复用已有附件定位／解密能力，核对该事件实际指向的图片内容与冻结意图，内容证明缺失不会标记 `ui_observed`。短暂观察内出现多张新出站图片会拒绝关联。微信可能重编码，不能用输入 SHA-256 等于接收文件哈希作为收件条件。内容核验先比较 EXIF 规范化后的完整像素；有损重编码仅在两图均不透明、短边至少 64 像素、宽高比差异不超过 1% 时，比较 64×64 重采样 RGB，要求平均通道误差不超过 3/255、最大不超过 48/255。这是保守的关联证据，仍须结合本次 GUI 与独立收件证据。本地 `ui_observed` 仍不是独立收件确认；专用桌面在操作期间不得手动切换／另发图片，现有标题型 UI 识别的残余边界仍然存在。
