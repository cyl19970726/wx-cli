## 分工与工作路径（重新委派时适用）

远端开发者在独立 checkout 和短期 `codex/` 分支实现，保持改动聚焦，并交付提议的变更、提交及隔离构建结果。不得合并到基线、发布 release 或把未经本地审查的版本装到 live runtime。本地负责人独立检查完整 diff、状态兼容性和证据，复跑相关检查，并决定是否接受。需要 live 部署时，由本地负责人在该项工作已获授权的范围内协调；本文件和开发分工本身不授权合并、发布、升级或其他外部变更。

本任务已经批准的测试身份、会话和动作授权持续适用于明确范围内的验证；不要对同一已批准动作重复询问。它不扩展到其他身份或会话，也不构成合并、发布或 live runtime 升级的授权。原生 helper 或运行时升级需另行明确纳入工作范围，并保留原状态与回退材料：停稳 writer，备份并保留状态，检查签名、权限、绑定、consumer/cursor、pending 和 outbox。不得为了通过测试删除或重建状态。

## 首项验收矩阵

| 范围 | 通过条件 |
| --- | --- |
| 离线回归 | 按 [贡献指南](../CONTRIBUTING.md) 运行受影响检查；合并前复跑仓库要求的 Rust、Python、Swift 与公开源码检查。记录命令、Python/工具版本、通过/忽略数量与失败，不把原有忽略算作通过。 |
| 导航与读取 | 在专用桌面有界验证目标私人会话及测试群的准确 focus；读取正确分页、发送者/方向和游标。读取不得调用模型、启动后台或修改源数据库；不把有限历史当完整服务器历史。 |
| 写入与收件 | 经授权后各做所需的合成写入。核对本地出站事件属于正确会话和 talker，原意图只产生一次；另行取得收件端确认。`ui_observed` 只是本地证据，不代替收件确认。重复同一 request 应为幂等且不再次提交。 |
| 故障与状态 | 目标不匹配、focus 失败、证据缺失或状态不明时立即停止，保留原 request/outbox，不换 ID、不循环重试。对源数据库做前后只读检查；状态升级需证明 channel、consumer/cursor、pending 和 outbox 保留且有可用回退。 |
| 范围 | 只测试本任务授权的测试身份与会话；不新增协议/hooks、不读取其他用户数据、不实现多常驻 Agent。任何未通过项标为未通过或未验证，不用离线测试替代现场验收。 |

## 交接材料

每次交接提供：提交 SHA 与简短变更说明；完整测试命令、工具版本、通过/忽略数量；脱敏证据索引（检查名称、结果及私有证据的本地索引，不含真实身份、消息正文或截图）；失败、未验证项、未决问题及下一步；如触及运行时，提供 helper 版本/hash、状态保留检查与回退位置。详细私有证据留在忽略目录或受控主机。本地负责人据此独立复核后决定是否接受。
